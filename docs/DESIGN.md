## 1. 二维显式离散

单位正方形内求解 $u_t=\alpha(u_{xx}+u_{yy})$，四边零温，初值 $\sin(\pi x)\sin(\pi y)$，解析解为 $e^{-2\alpha\pi^2t}\sin(\pi x)\sin(\pi y)$。每个方向有 $N$ 个区间和 $N+1$ 个节点，时间分为 $M$ 步，$h=1/N$、$\Delta t=T/M$。

取 $i$ 为行坐标、$j$ 为列坐标，用连续的 `double` 存储二维温度场，串行全局下标对应 `i*(N+1)+j`。内部节点采用

$$
U_{ij}^{n+1}=U_{ij}^n+r\left(U_{i-1,j}^n+U_{i+1,j}^n+U_{i,j-1}^n+U_{i,j+1}^n-4U_{ij}^n\right),
\qquad r=\alpha\Delta t/h^2\le1/4.
$$

这与任务书的中心权重 $(1-4r)$ 写法等价。需检查输入有限、$\alpha,T>0$、整数 $N\ge2,M\ge1$、稳定性以及数组规模可表示且可分配；具体接口和浮点边界判断在 M1 冻结。

串行用两个数组保存旧层与新层。初始层按全局坐标生成，四边显式置零；每步只从旧层读取内部更新所需的五个值，保持新层边界为零，更新完整层后交换数组角色。奇偶步均须取实际最终层。解析解只用于初值与验证，不能用于替代差分推进。

## 2. MPI 内部行分块

沿行坐标 $i$ 连续分配 $K=N-1$ 行内部节点，进程数为 $P$，rank 为 $p$：

$$
q=\lfloor K/P\rfloor,\quad s=K\bmod P,\quad
m_p=q+[p<s],\quad o_p=pq+\min(p,s).
$$

rank $p$ 拥有全局行 $i=o_p+1,\ldots,o_p+m_p$，每行包含 $j=0,\ldots,N$。行内只有 $j=1,\ldots,N-1$ 参与更新；左右两列为物理零边界。每个内部节点仅由一个 rank 更新。

基线设计限制 $1\le P\le N-1$，保证每 rank 至少一行。超过范围时所有 rank 一致报错退出，不静默丢弃进程。空任务进程支持属于后续可选改进，不是 MPI 自身限制。

本地双数组各含 $(m_p+2)(N+1)$ 个元素：本地行 $1..m_p$ 为拥有行，行 $0$ 和 $m_p+1$ 是上下 halo；本地行 $k$ 对应全局行 $o_p+k$。初值由全局坐标生成，不能将各子域重新当作单位正方形。

每个时间步执行：

1. 设置当前旧层的物理零边界，非周期端部邻居用 `MPI_PROC_NULL` 表示；从它接收不会自动把缓冲区置零。
2. 使用两次匹配的 `MPI_Sendrecv`，将首尾拥有行发送给上下邻居，并接收旧层的上下 halo。完整行连续传输，两个方向使用不同标签，发送和接收缓冲区不重叠。
3. 更新全部本地内部节点，保持新层的物理边界为零，然后交换新旧数组角色。

单进程和每 rank 一行使用相同流程。基线先完成 halo 交换再计算，不引入通信计算重叠，也不在每个时间步增加全局屏障。参数由 root 使用共用 CLI 解析并按类型广播；统一错误处理见第 7 节，避免某个 rank 单独返回而其他 rank 仍等待通信。

最终输出或逐点对照需要全局温度场时，使用 `MPI_Gatherv` 按全局顺序收集拥有行，计数为 $m_p(N+1)$，相对首个内部行的位移为 $o_p(N+1)$，root 补齐首末物理边界行。halo 不参与收集。实现时须检查 MPI 计数/位移范围，root 额外内存及各 rank 的退出路径。

## 3. 两层正确性验证

第一层检查离散算法是否正确实现：对同一输入，分别比较 MPI/OpenMP 与独立串行全局温度场，计算 $D_\infty=\max_{i,j}|U_{ij,\mathrm{parallel}}^M-U_{ij,\mathrm{serial}}^M|$，其中 parallel 明确标为 MPI 或 OpenMP。不要求所有浮点实现逐位一致，具体容差在实现阶段记录。

第二层检查数值解与连续模型：计算 $E_\infty=\max_{i,j}|U_{ij}^M-u(x_i,y_j,T)|$。MPI 仅统计拥有节点的局部误差，再以最大值归约，避免重复统计 halo；物理边界误差应为零。OpenMP 在共享最终全场上验证连续解析误差，不能仅以与串行一致代替解析误差检验。

在固定 $T,\alpha$ 下，令 $N$ 加倍、$M$ 增至四倍可保持 $r$ 不变。时间一阶、空间二阶格式的联合误差通常为 $O(\Delta t+h^2)$，在进入渐近区间且无特殊误差抵消时预期误差约缩小四倍；不能将这一趋势当作所有参数下的精确比例。选取测试参数及容差时避免特殊系数抵消掩盖错误，并保留真实数据。

## 4. 性能测量设计边界

主要计时范围为时间推进循环；MPI 包含 halo 交换、本地更新和数组交换，OpenMP 包含并行内点更新、每步必要同步和缓冲交换；初始化、最终收集、解析/串行验证与文件输出放在该计时之外并在报告中明确。串行采用对应循环范围；MPI 在开始计时前作一次屏障，每 rank 用本地墙钟差计时，再取最大耗时。不能用不同 rank 的绝对时钟直接相减。

两种并行方式的主加速比均使用同一算法、同等优化配置的独立串行循环耗时 $T_s$，以 $T_s/T_p$ 和 $T_s/(kT_p)$ 计算加速比与效率，MPI 取 k=P、OpenMP 取 k=Q，均采用实际使用的资源数并同时记录请求值。MPI 单进程和 OpenMP 单线程基线须单独标注，不能替换独立串行基线。OpenMP 由同一计时线程读取起止墙钟时间；团队创建/销毁是否纳入、进程/线程绑定、实验规模及重复次数由 M4 冻结，避免拿包含不同阶段的时间直接比较。

固定 $N,M,T,\alpha$ 做强扩展。扩大规模时累计内部更新量为 $M(N-1)^2$；固定 $T$ 且保持稳定性会使加密后的 $M$ 随 $N^2$ 增长，因此必须同时说明空间与时间工作量。M4 再确定具体扩展方案，不预填性能数据或最低加速目标。

## 6. M1 串行接口与验证标准（2026-11-10）

串行程序 `heat_serial` 采用 `--N --M --T --alpha` 命名参数，可任意排序及独立覆盖；默认 `20,400,0.1,1`。步数 M 是输入，实际推进恰好 M 步，物理终点为 T；不累计浮点时钟作为停止条件，不自动调整不稳定输入。CLI 与 CSV 完整约定见 README。

`src/heat.cpp` 将参数检查、正弦初值、单步内核和完整求解分开。内部行 i 对应 x、列 j 对应 y，索引 `i*(N+1)+j`。两个连续 `double` 数组每步只更新内部节点，显式覆盖新层四边为零，完成后 `swap`；返回当前旧层，奇偶步路径相同。内核检查数组大小与别名，禁止原地覆盖；求解循环不调用解析解。解析解及最大误差在推进完成后计算。

检查整数与浮点文本完整解析、范围与有限性，再检查节点乘法、双数组字节数及 `vector::max_size()`；分配异常由 CLI 报错退出。不设任意 N/M 工作量上限，可表示规模不保证机器有足够内存。`dt=T/M` 存为 double；r 使用 long double 中间运算按 `alpha*T/M*N*N` 计算，减少提前上溢/下溢，随后转为 double，要求 dt/r 有限且正。稳定性在较宽中间值上严格比较 `r≤0.25`，无 epsilon 宽限、不截断；非常靠近上限的十进制输入按已解析浮点值判断，必要时用户增大 M。这里不承诺任意极端参数下的高精度计算。

| 检查 | 输入与判据 | 独立依据 |
| --- | --- | --- |
| 初值 | N=4 的代表内点 1/2、√(1/2)、1；N=3 内点均 3/4；边界严格为 0 | 特殊角正弦值 |
| 非对称二维手算 | N=3，内部旧层 `[1,2;3,4]`，r=1/8，新层 `[1.125,1.625;2.125,2.625]`；旧层不变，新层预填哨兵 | 人工代入五点权重，与正弦基准分开检查索引 |
| 奇偶步与稳定性端点 | N=2、r=1/8，M=1,2,3,4,9,10，中心应为 `2^(-M)`；r=1/4 一步中心归零 | 唯一内点标量递推 |
| 全场离散模态 | N=7,M=7/8,T=0.01,alpha=0.3，逐点比较 `U0*g^M`，`g=1-8r sin²(pi/(2N))` | 离散正弦特征模态；不复制推进循环，仅用于测试 |
| 非法参数 | N/M 越界、负数、NaN/Inf、文本残余、重复/缺值参数、派生量上溢/下溢、规模溢出、r 上限及相邻浮点值 | 接口和稳定性约束；CLI 应退出 2 且 stdout 为空 |
| 解析误差与基本加密 | T=0.1,alpha=1，N=20/40/80，M=400/1600/6400，r=0.1 | E_inf 上限分别 `2e-4,5e-5,1.25e-5`，相邻误差比在 `[3.8,4.2]` |
| 输出 | CSV 表头、行数、全场坐标、数值/解析/误差列、摘要最大值；Linux `/dev/full` 失败应退出 1 | Python 标准库独立读取，并逐点对照离散模态与解析解 |

小规模手算和离散模态统一绝对容差 `1e-13`，CSV 解析列/误差列采用 `1e-14`，坐标 `1e-15`；边界要求严格零。阈值给双精度舍入留余量，同时远小于可检出的错层、漏邻居误差。测试使用异常报告失败，Release 中也不会因 NDEBUG 禁用断言。

基本加密选 r=0.1，避开正弦模态主误差在 r≈1/12 时的特殊抵消；参数的离散模态预估误差约 `1.1262e-4,2.8181e-5,7.0470e-6`，上限约留 1.77 倍余量。预估仅用于设计阈值，最终证据是实际差分输出，见 `validation/m1.log`。另逐点检查有限性、非负性、最大值不超过 1、转置/镜像对称性。此处仅基本回归，M3 仍需完善系统验证，不能据此宣布所有网格具有精确四倍误差比。

CMake ≥3.20、C++17、CTest；默认 Debug，无 GoogleTest/网络依赖，测试需 Python 3。6 项 CTest 均有 30 秒超时，CLI 子进程另有 10 秒超时。M1 未引入性能计时；M4 再实现并核查与 MPI 可比的循环计时。

## 7. M2 MPI 实现与回归约定（2026-11-10）

`src/heat_mpi.cpp` 实现第 2 节分块和推进，`main_mpi.cpp` 管理 MPI 生命周期、参数广播及统一退出。`cli.cpp` 为两个独立程序共用的解析/输出，串行 `heat.cpp` 的数值实现不变。各 rank 通过 `MPI_UINT64_T` 收到 N/M，通过 `MPI_DOUBLE` 收到 T/alpha；不广播带填充的结构体。当前同一 MPI 作业假定同构可执行程序和 size_t 范围，编译时要求 size_t 不宽于 uint64_t。所有 rank 以同一参数计算 h/dt/r，不改变终止时刻。

计数采用传统 MPI `int` 接口。额外保守限制 `(N-1)(N+1)≤INT_MAX`，并检查行宽，保证所有 count、相对位移及其终点可表示；乘法先用除法检查。此限制与进程数无关，避免 P=1 时溢出，支持范围有意比部分大计数实现更小，不影响独立串行范围。在当前 32 位 int 环境下 N≤46340；边界检查测试不分配该大网格。串行 validate 已检查全场/双缓冲规模，MPI 本地两层最多为全场两层，root 还需完整结果及 counts/displs，故可表示不等于实际内存足够。

通信表（行宽 w=N+1，拥有行数 m）：

| 调用 | 发送 | 接收 | 标签 |
| --- | --- | --- | --- |
| 第一次 Sendrecv | 首行 old+w → up | down → old+(m+1)w | 71 |
| 第二次 Sendrecv | 尾行 old+mw → down | up → old | 72 |

两次均传输 w 个 double，收发区域不重叠，m=1 时也成立。物理 halo 每步交换前显式清零，拥有行两端列在两层中始终为零。所有内点从旧层更新到 next，交换 vector 角色；无逐步全局屏障，无通信计算重叠。最终仅收集 old 的拥有行到 root `global+w`，全场初始化为零以保留首末边界行。每 rank 对拥有内点计算局部解析误差，以 `MPI_Reduce(MPI_MAX)` 汇总；root 再用重建全场的最大误差交叉核对。两者均选取已有非负误差值而非求和，因此在本实现中应相同；这不要求 MPI 与串行数值逐位相同。

| 情况 | 统一处理 |
| --- | --- |
| 独立 --help | 只有 root 输出一次帮助并广播状态；所有 rank Finalize，成功返回 0，帮助输出失败返回 1；帮助不受默认 N 的进程数限制 |
| 参数非法、不稳定、P>N-1、计数超限 | root 在分配前检查，广播退出码 2；无 CSV，所有 rank Finalize |
| 本地/root 网格或收集元数据分配异常 | 每 rank 捕获本地异常，以 Allreduce(MIN) 合并成功标志；任意失败则所有 rank 抛运行异常，经入口统一 Finalize/退出 1 |
| 正常求解后的 root 验证/输出失败 | root 记录退出码 1，广播给所有 rank 后 Finalize；输出可能已有部分内容，调用者须检查退出码 |
| MPI 调用报告错误 | communicator 使用 MPI_ERRORS_RETURN；检查返回码，输出操作名与 MPI 错误信息，再 MPI_Abort 整个 communicator，避免继续进入不再可靠的集合调用 |
| Init / Finalize 错误、外部强制杀进程 | 初始化成功前及结束后无可用 communicator，返回失败；不承诺普通 MPI 对真实进程丢失或 OOM killer 的恢复能力 |

`solve_mpi` 是集体接口，调用方必须保证所有 rank 使用相同且已验证参数、调用顺序一致；入口通过 root 校验及广播保证此前置条件。该接口不是可由部分 rank 任意调用的容错库。

新增 `heat_mpi_p1` 至 `heat_mpi_p4`，默认最大资源 4，可用 CMake 缓存 `HEAT_MPI_TEST_MAX_PROCS=1..4` 降低；此值是调用者选择的测试资源，不代表自动探测或已运行资源。每项 TIMEOUT=120 秒、PROCESSORS=P，每次子进程 15 秒超时，超时杀死整个启动器进程组。传递 FindMPI 的 MPIEXEC_EXECUTABLE、NUMPROC_FLAG、PREFLAGS、POSTFLAGS，不硬编码 MPI 安装位置。原 6 项串行测试及四位小数 check 入口继续保留，check 依赖所有测试可执行程序。

每个 P 运行 N=20/M=400/T=0.1/alpha=1；另以 N=P+1、M=1/2/7/8 检查每 rank 一行和奇偶步，以 N=2P+2、M=7/8 检查不均匀分块（P>1），后两组 T=0.01/alpha=0.3。P=1 另检查 N=2/M=1/T=0.0625 的 r=1/4 端点。逐点检查完整 CSV 顺序/坐标/行数、严格零边界、有限性、离散模态最终层、连续解析值、误差列和 E_inf；N=20 仍要求 E_inf<2e-4。MPI/串行逐点最大差采用绝对容差 1e-13，沿用 M1 小规模离散模态容差，给双精度舍入留余量，远低于可检出的错层或漏邻居误差；不宣称任意 N/M 均适用，也不要求逐位一致。CSV 解析与误差列 1e-14、坐标 1e-15。

错误回归覆盖超限 P、整数溢出、非法/重复/缺值参数、非有限值、不稳定输入、派生量下溢和 MPI count 范围。`/dev/full` 必须在 rank 内重定向；重定向启动器的 stdout 只影响启动器转发，不能测试求解器输出错误。首轮测试因此失败，原始输出保留在 `validation/m2-initial.log`。Linux/GNU 兼容链接器下，测试专用可执行程序替换一次 operator new 或包装 MPI_Sendrecv，分别验证 root/worker 分配异常的集体路径及通信错误的 Abort 路径；生产求解器没有故障开关。分块测试遍历 N=2..25 的所有合法 P/rank，并检查 INT_MAX 跨度边界，不进行大分配。其他平台未构建注入程序时明确输出“not run”。这类受控错误注入不等于真实硬件故障或耗尽内存实验。

本轮只做 M2 回归，未新增正式性能计时；第 4 节为 M4 设计。系统化加密、多机及更大进程矩阵留待用户授权后进入后续阶段。

## 8. M2b OpenMP 设计基线（2026-11-10，尚未实现）

用户已确认新增独立 `heat_openmp`，不引入混合并行。沿用第 1 节二维五点格式、零边界、正弦初值、稳定性和双精度要求，复用已有命名参数 `--N --M --T --alpha`、默认 `20/400/0.1/1`、全场 CSV 与解析误差摘要。线程控制接口及实际构建/运行方式在 M2b 实施前确定，本节不是当前可运行功能说明。

单进程内共享两个完整的 `(N+1)^2` 连续数组作为 old/next；内部行采用静态调度，每行的内部列由取得该行的线程更新。循环索引和临时数值由各线程私有，模型参数和旧层只读，每个新层内点只由一个线程写入。共享存储中的邻居值直接读取，不增加 MPI halo、进程通信或最终 Gatherv。

每个时间步先保证两个数组的物理边界保持零，再完成全部内部点从 old 到 next 的更新；所有线程完成整层后，由一个线程统一交换共享缓冲的角色，并在下一步读取前同步。必须同时保证“更新结束后才能交换”和“交换对所有线程可见后才能继续”，不得用省略同步的方式让线程读到不同时间层。最终输出选择实际完成 M 步的数组，覆盖奇偶步路径。内存分配、输入校验和错误报告在并行计算前后统一处理，不能让异常直接跨越并行区域。

用 Q 表示线程数，线程编号与 MPI rank 分开说明；记录请求线程数和实际使用的团队线程数。Q 大于 N-1 时允许部分线程无内部行可更新，但仍须参与所需同步，不套用 MPI 的 P≤N-1 拒绝规则。具体静态行归属按实现选定的调度方式说明并验证，不能未经核查就声称它与 MPI 的余数分块公式相同。

M2b 在实际可用资源内验证单/多线程、行不能均分、线程多于内部行、奇偶时间步、严格零边界、全场输出、串行逐点一致性、连续解析误差、非法/不稳定输入及错误退出，测试均设超时；保留串行/MPI 回归及四位小数 check。容差及测试矩阵在实施前结合既有 M1/M2 标准确定并记录依据，不要求无依据的逐位一致。M3 再完善三种实现的系统化联合加密和误差验证，M4 开展正式性能比较。
